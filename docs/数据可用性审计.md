# 首阶段数据可用性审计

审计日期：2026 年 10 月 23 日（北京时间）。本报告记录实际下载文件和实际检查结果；当前尚未进行正式坐姿分类训练。

## 结论

**SPD_YOLO 不适合作为本项目“原始 RGB 图片 → YOLO11n-pose → 四类坐姿分类”路线的主训练集。按项目计划转入 COCO 人物图片筛选与人工坐姿标注。**

主要原因：下载的图片是黑底骨架渲染图；全部验证图与训练图字节级重复；原始九类语义不能直接生成目标四类；去重后只有 544 张图片；缺少可核实的人员、视频和视角元数据。

这份数据仍可用于独立的骨架图分类探索和审计参考。不能将其当作原始人体照片喂给 RGB 姿态提取器，也不能凭数据集名称宣称本项目四类数据已准备完成。

![九类原始骨架样例](../runs/stage1/dataset_audit/class_contact_sheet.jpg)

TXT 是 YOLO **目标检测框**格式，每行 `class_id cx cy width height`；不存在逐关节坐标或原始 RGB 图。实际 696 行标注均有 5 项、有效类别编号和归一化范围，未发现格式错误或孤立标签文件。部分图片有多个目标框，因此“目标框数”大于“有标签图片数”，不能混用。

## 与本项目目标的符合程度和后续入口

| 项目要求 | 审计结果 |
|---|---|
| 原始人体 RGB → YOLO11n-pose | 不符合；本包已是渲染骨架 |
| 800–1,200 个有效样本 | 不符合；544 张唯一图像，且 3 张缺标签 |
| 每类至少 150 个四类样本 | 不符合；原九类每类仅 68–92 个框，还包含验证重复 |
| 端正、低头、上身前倾、侧倾 | 不具备可直接采用的四类真值 |
| 可审计且无泄漏的数据划分 | 不符合；验证全部重复，且无独立测试集 |
| 跨人、跨视角评估依据 | 不具备所需元数据 |

因此，保留 SPD 的原始文件和审计结果，**不纳入主训练清单**。后续使用官方 COCO-Keypoints 中可辨认坐姿的 RGB 图片，保留 COCO 图像／人物／许可编号，并按项目规范人工补充四类坐姿标签；COCO 原始关键点标签不能代替坐姿标签。真实单图推理验收应使用 COCO 等来源清晰的 RGB 人体图片，不能用此包骨架图充数。小规模下载与推理成功也不能代替完整 800–1,200 张四类数据可用性验收。

### 几何筛选、候选裁剪与分组限制

- 第一轮根据已有关键点的可见性、单个关键点人物注释、边框尺寸和膝角筛得 **115 个人物／115 张原图候选**。其中 28 张属于 ND 许可（ID 3 为 21 张、ID 6 为 7 张），排除后剩 **87 张**进入下载池。这个数量只表示通过当前候选规则；弯膝也可能来自跑步、骑行或其他活动，不能证明坐姿。
- 第二轮结合椅子实例关联和人物几何得到 **74 个人物候选、54 张原图**。受 1 张原图下载失败影响，实际生成 **73 个人物裁剪、来自 53 张原图**；73 个 `crop_path` 全部存在。记录保留图像 ID、人物 annotation ID、原 bbox、裁剪矩形和许可。
- 本次查看 `candidate_ranking.json`、`candidate_pool.json`、`crops.json` 时，所有候选 `label` 均为空，chair 的 `view` 均为 `unknown`。`head_y`、`torso_angle`、椅子关联与膝角仅帮助排序和提出人工检查对象，**不能产生坐姿真值、视角真值或四类验收指标**。后续人工试标与复核结果应另行记录，不能回写成“原始 COCO 坐姿标签”。
- 73 张裁剪包含同一原图中的不同人物。同一 COCO image ID 的全部裁剪、派生图和重复处理必须属于同一项目划分；人物 annotation ID 不能替代跨图片的人员身份 ID。COCO 这两份 JSON 没有本任务所需的人员身份或连续拍摄／原视频分组，不应宣称严格跨人隔离。
- 当前取得的是 **COCO 官方 val2017 子集**，处于本项目的候选审查阶段；目录名和注释可用不等于本项目已建立训练／验证／测试集合。正式使用前仍须人工筛选四类、复核标签、去重、记录项目分组及划分，并确保试标或评估样本不会随后被用于声称独立的最终测试。
