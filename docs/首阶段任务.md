## 1. 数据来源审计

先检查 [SPD_YOLO 候选入口](https://www.kaggle.com/datasets/xiaokonglong80/spd-yolo)。下载需要账号或条款确认时按其公开要求操作，保留版本、来源网址、下载日期、许可文本和原始标注。项目尚未完成上述审计。

为每个来源建立一份记录，填写：

| 检查项 | 当前记录 |
|---|---|
| 是否可下载、版本/文件清单/校验和 | 待填 |
| 数据许可、图片许可、是否允许课程使用与再分发 | 待填 |
| 原始类别、四类可直接采用或需重新人工标注的部分 | 待填 |
| 可辨认坐姿数量、每类预估样本量 | 待填 |
| 原始人员/视频/拍摄组身份与官方划分 | 待填 |
| 重复、近重复、原图裁剪与跨集合风险 | 待填 |
| 是否采用以及依据 | 待填 |

若类别或数量无法支持计划，转向 [COCO-Keypoints](https://cocodataset.org/) 中的可辨认坐姿图片并人工标注；关键点原标注本身不是坐姿真值。核实图片许可和来源，不假定全体图片具有相同授权。目标为 800–1,200 个有效公开样本、每类至少 150 个；达不到时记录实际缺口并调整采集安排。

## 2. 试标与清单

按 [标注规范](标注规范.md) 先选少量四类、不同视角样本试标，记录不确定与复合动作的剔除原因。确认可复核后才扩充标注，并按来源前缀填写真实身份编号；先按组确定划分，再从视频抽帧。

将真实标注填入 `data/manifest.csv` 后，从项目根目录执行：

```bash
python3 -m posture audit --manifest data/manifest.csv
```

人工检查图像重复内容和审计输出的身份缺失限制。若没有可采用的官方划分且至少有三个独立组，再创建新划分；已有非空分配不能用本命令重划：

```bash
python3 -m posture split --manifest data/manifest.csv --output data/manifest_split.csv --seed 42
python3 -m posture audit --manifest data/manifest_split.csv --require-split
```

输出文件不会覆盖已有清单；重新试验应使用新的文件名并保留旧记录。分配近似 70%/15%/15%，组大小可能造成比例和类别数偏斜，要人工查看分布。

## 3. 本机真实推理和资源测试

先从项目根目录运行只读环境检查：

```bash
python3 -m posture check
```

需要时安装视觉依赖：`python3 -m pip install -e '.[vision]'`。从 [Ultralytics 官方 YOLO11 说明](https://docs.ultralytics.com/models/yolo11/) 获取 `yolo11n-pose.pt`，核对使用许可并放入 `models/`。记录实际来源和权重校验和。框架不自动下载模型。

建立只含一张真实、有人工标签图像的小清单，例如 `data/single_image.csv`，字段同主清单，且为该样本填写真实预定 split。运行：

```bash
python3 -m posture extract --manifest data/single_image.csv --output data/processed/single_image.npz --device mps
```

指定设备不可用时保留原错误并记录；明确另行以 `--device cpu` 复测，不能把 CPU 成功写作 MPS 成功。单图结果检查如下：

- [ ] 图像确为单人坐姿，来源和许可可追溯。
- [ ] `single_image.metadata.json` 记录对应清单和权重；无拒识时特征为 25 维有限数值。
- [ ] 若拒识，区分无人、多人、关键点遮挡、图像读取失败和环境错误，保留实际原因。
- [ ] 记录模型加载/首次运行耗时；再独立测量预热后的图像推理时间，不将下载或加载时间混作稳态速度。
- [ ] 用同一测量方法记录进程峰值内存和可用的 MPS/GPU 内存信息，注明工具、图像尺寸、设备和运行状态；未测项目写“未测”。
- [ ] 补充三个视角的少量真实试拍，确认髋/肩可见性；侧面若频繁拒识，保留为困难条件，不编造关键点。
