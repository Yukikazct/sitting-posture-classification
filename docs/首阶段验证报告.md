## 2. 两张真实图像的推理结果

输入清单为 `data/processed/stage1_public_pilot.csv`；本次记录的清单 SHA256 与当前文件一致。两张原始 RGB 图像均来自 COCO 2017 validation，已由助手查看，图片及骨架叠加输出均实际存在。清单的 `upright` 是**助手视觉试标提案，人工确认待完成**，两行暂放 `val` 仅服务于可行性检查；它们不是覆盖四类的正式标注集，也没有用于报告分类准确率。

推理配置为 `imgsz=640`、人物置信度阈值 0.25、必要关键点置信度阈值 0.30，使用固定官方权重和 MPS。

| COCO 图像 ID | 试记视角 | 原图宽 × 高 | 检出人数 | 特征状态 | 预热后均值 / P95 |
|---|---|---|---|---|---|
| `000000051610` | 侧面 | 640 × 427 | 1 | 有效，25 维有限数值 | 9.410 / 11.042 ms |
| `000000368212` | 正面 | 478 × 640 | 1 | 有效，25 维有限数值 | 9.340 / 10.279 ms |

骨架输出：[侧面示例](../runs/stage1/real_pose_mps/overlays/000_coco_val_000000051610.jpg)、[正面示例](../runs/stage1/real_pose_mps/overlays/001_coco_val_000000368212.jpg)。侧面示例的一只耳朵置信度不足，按既有规则置零，鼻、双肩和双髋仍达到阈值；这说明可选耳朵缺失能够正常处理，不代表被遮挡身体部位具有人工确认的位置。

## 3. 耗时、内存与复现方法

测量脚本为 `scripts/benchmark_pose.py`。脚本显式冻结姿态模型，逐图预先解码图像，首次预测后额外预热 3 次，再计时 10 次；每次计时前后同步 MPS。两图共得到 20 次预热后计时。

| 测量项 | 实际结果 |
|---|---|
| 模型加载与设备迁移 | 0.132 秒 |
| 模型首次推理 | 6.309 秒 |
| 第二张图首次调用 | 0.304 秒 |
| 两图预热后推理均值 / 中位数 | 9.375 / 9.171 ms |
| 模型融合前参数量 | 2,874,462 |
| 进程峰值 RSS（`resource.getrusage`） | 570,228,736 bytes，约 543.81 MiB |
| 运行期间 RSS 采样最大值（`psutil`，间隔 10 ms） | 570,228,736 bytes，约 543.81 MiB |
| 同步预测后观测到的最大 MPS 张量分配 | 25,924,352 bytes，约 24.72 MiB |
| 同步预测后观测到的最大 MPS driver 分配 | 130,367,488 bytes，约 124.33 MiB |

首次调用会包含后端和模型预测流程的初始化成本，不能用它代表持续推理速度；第二张图的首次调用也没有计入预热后的统计。预热后时间包含 `YOLO.predict` 的预处理、姿态前向与后处理，**不包括**图像文件读取、画图、25 维特征生成、MLP 分类、时序提醒、摄像头采集及显示。因此不能把其倒数写成项目端到端 FPS，也不能将两张图的低延迟视为长时间稳定性或跨视角分类结论。

进程 RSS 的观测范围还包含该进程内的加载、图像处理等工作，不仅是神经网络张量。MPS 数据来自每次稳态预测同步后的查询，可能遗漏推理内部瞬时峰值，不能称为真实设备峰值；driver 分配与张量分配也不是两个独立内存池。Apple Silicon 使用统一内存，RSS 与 MPS 统计可能重叠，**不能把这些数相加作为总占用或显存需求**。本次没有测整机峰值、持续视频运行或训练峰值内存。

从项目根目录复现（使用新的输出目录，脚本不会覆盖既有实验）：

```bash
YOLO_CONFIG_DIR=runs/stage1/environment/ultralytics \
  .venv-sitting-posture/bin/python -m scripts.benchmark_pose \
  --manifest data/processed/stage1_public_pilot.csv \
  --output runs/stage1/real_pose_mps_REPRO \
  --device mps --warmup 3 --repeats 10
```

该命令只读取本地官方权重和已有真实图片，不采集摄像头，不训练分类器。复测耗时可能随后端缓存、系统负载和温度变化，应保留新的测量文件。

## 4. 本机训练可行性与边界

计划中的 MLP 为 `25 → 64 → 32 → 4`，按当前 `posture/model.py` 含 3,876 个可训练参数。`posture/training.py` 读取已经缓存的关键点特征，仅训练 MLP；不会同时训练 YOLO。对计划中的 800–1,200 个样本，该规模在 CPU 或 MPS 上均适合本机开展，24 GiB 统一内存具备充足的起步条件；真实姿态提取也已在本机 MPS 跑通。

这属于硬件和代码路径的可行性判断，不是正式训练已经完成。当前未得到真实四类训练集上的耗时、内存曲线、准确率或 Macro-F1，也未测本机 CPU 上真实 YOLO 的速度。小模型可能受设备调度开销影响，不能预先保证 MPS 一定比 CPU 更快。正式数据齐备后仍需用相同配置记录 CPU/MPS 实际训练耗时，并保留验证集选择和三个固定随机种子的结果。

代码显式请求不可用的 MPS/CUDA 时会报错，不能将其他设备的成功写成原设备成功。当前方案不要求 CUDA，也未验证 YOLO 微调、更大姿态网络、大批量原始图像训练或多人实时处理。
